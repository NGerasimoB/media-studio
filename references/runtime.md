# Локальные инструменты и доставка

## Подключение среды

Перед работой найди нужные программы и проверь их версии. Используй среду текущего компьютера, а не пути из чужой установки. Для PowerShell:

```powershell
Get-Command ffmpeg, ffprobe, node, python -ErrorAction SilentlyContinue
```

| Инструмент | Что проверить |
|---|---|
| FFmpeg / FFprobe | Доступная команда или полный путь к исполняемому файлу |
| Remotion | Установленный CLI, React/Remotion-пакеты, конфиг проекта и браузер |
| Hyperframes | Установленный CLI, его локальная справка и Chrome Headless Shell |
| Python для таймкодов | Python 3.10+; remap использует стандартную библиотеку |
| Python для распознавания | faster-whisper, CUDA-библиотеки и локальный кэш large-v3 |

Для монтажа без распознавания и новой анимации не нужны все инструменты из таблицы. Уже установленная рабочая версия имеет приоритет. Используй существующие обёртки и окружения, если они есть; не меняй PATH пользователя ради проекта. Новая установка или обновление выполняются в рамках отдельной задачи настройки, когда этого требует выбранный режим. Не подменяй обычную команду сборки на `npx ...@latest`.

## Remotion

Работай в папке проекта. Найди доступную установку CLI и пакетов React, Remotion, bundler, renderer; captions нужны при использовании соответствующего API. Переиспользуй установленный набор. Если пакеты находятся вне проекта, проверь разрешение модулей и задай webpack resolve aliases для фактических путей.

Найди совместимый Chrome/Chrome Headless Shell до первого рендера. Чтобы CLI не скачивал второй браузер автоматически, укажи фактический проверенный путь в конфиге. Например, при доступном в проекте `@remotion/cli`:

```javascript
const {Config} = require('@remotion/cli/config');
Config.setBrowserExecutable('C:/path/to/chrome-headless-shell.exe');
```

Путь в примере заменяется на реально найденный исполняемый файл. `src/index.jsx` регистрирует Root и Composition, `public/` содержит локальные ассеты. Не записывай проект в папку установки движка. Форма команды, где `remotion` обозначает найденный CLI или локальную обёртку:

```shell
remotion render src/index.jsx Main out/final.mp4 --codec h264 --audio-codec aac --pixel-format yuv420p
```

Точный список флагов проверь у установленного CLI. Анимация зависит от `useCurrentFrame()` и `useVideoConfig().fps`; длительности Composition/Sequence и trimBefore считаются в кадрах. `staticFile()` адресует `public/`. Не используй обычные CSS-анимации, реальные часы, случайные значения без seed и сетевые запросы во время рендера. Секунды и миллисекунды субтитров явно преобразуются в кадры.

Если звук смонтирован отдельно, проще рендерить изображение на его фактическую длину и один раз объединить с WAV/FLAC. Наличие аудиофайла в public не означает, что он попал в экспорт; проверь поток. Для preview можно открыть Studio. Когда заказан готовый ролик, отдельное согласование каждого локального рендера не требуется; явно заданные пользователем точки согласования сохраняются.

## Hyperframes

Для HTML/GSAP используй контракт установленной версии и её локальную справку. Если установлен `brag`, технические ссылки можно найти в его `references/hyperframes/` (core, animation, creative, keyframes, cli). Наличие этого соседнего навыка не является условием работы Media Studio.

Из подключённых справок используй технические правила; порядок работы и согласований определяется текущей командой и `media-studio`. Заказ готового ролика разрешает локальный рендер без отдельного подтверждения. Запрос только на план/превью и явно заданные пользователем точки согласования сохраняют свою силу.

Основные условия: размер и длительность composition заданы; идентификатор корня совпадает с `window.__timelines` key; одна детерминированная paused timeline; временем и видимостью `.clip` управляет движок; у каждого `<audio>` есть уникальный id. Не смешивай произвольный CSS transform и GSAP transform на одном узле. Дожидайся локальных шрифтов/ассетов.

Используй `check`, проверку реальных кадров и `render` из установленного CLI. Возможности сверяй с `--help` и локальной документацией. Для Hyperframes проверь именно нужный движку Chrome Headless Shell. Не запускай `usage`, `auth`, `publish`, `cloud`, обновления или автоподключение новых навыков для локального экспорта.

## FFmpeg

Для новых выходов используй `-n` и отдельные пути. Сложный filtergraph храни в файле проекта; передавай subprocess argv массивом, не shell-строкой с пользовательским текстом. В PowerShell кириллические пути передаются как отдельные литералы; фильтры drawtext/subtitles дополнительно экранируют двоеточия, кавычки и обратные слеши.

Probe:

```powershell
ffprobe -v error -show_streams -show_format -of json '<source>'
```

Полная проверка декодирования:

```powershell
ffmpeg -v error -i '<final.mp4>' -map 0:v:0? -map 0:a:0? -f null -
```

Кадры для просмотра, пример для шестисекундного ролика:

```powershell
ffmpeg -n -i '<final.mp4>' -vf 'fps=1,scale=360:-2,tile=3x2' -frames:v 1 '<project>\review.jpg'
```

Сетка из нескольких кадров не доказывает плавность движения. Если вопрос именно в анимации, возьми последовательные кадры вокруг действия или просмотри короткий участок. Для длинного видео выбери интервалы по всей длительности и все изменённые стыки; не ограничивайся первой страницей contact sheet.

## Форматы и финальная проверка

При отсутствии другого требования практичный MP4: H.264, yuv420p, AAC, faststart. Сохраняй разумный FPS источника либо выбранный FPS анимации, не повышай его автоматически. Типовые размеры: 1920×1080, 1080×1920, 1080×1080, 1080×1350. Это варианты экспорта, не проверенные требования каждой площадки. Превью может иметь меньшее разрешение; не выдавай его за заказанный мастер.

Сверь ожидаемую длительность, пропорцию, количество кадров/потоков, A/V конец и размеры. Полностью декодируй конечный файл. Для речи проверь несколько пословных смен и стыков по итоговой временной шкале; для новой графики проверь причинное действие и читаемость. У длинного проекта проверь границы частей и дрейф синхронизации. Для прозрачного overlay нужен контейнер/кодек с alpha, а не обычный H.264.

Доставляй готовый файл и папку проекта. Новый код можно править словами; это не обещание редактируемого проекта Movavi/Premiere. Такой проект или совместимый interchange экспорт является отдельным результатом и требует фактически поддерживаемого формата.
