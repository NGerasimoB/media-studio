# Сцены на общем времени видео

Читай при создании новой анимации. Основной маршрут остаётся в `media-studio`: монтаж речи → выходные слова → действия → оформление → экспорт.

## Минимальный выбор

| Что нужно показать | С чего начать |
|---|---|
| Линия, схема, маска, диаграмма, движение вектора | SVG + кадровое время Remotion |
| Падение, столкновение, опора, отскок | Matter.js с предварительным расчётом состояний |
| Готовая HTML/GSAP-сборка | Существующий Hyperframes-проект |
| Сложные операции над контурами | Paper.js, если SVG уже недостаточно |
| Настоящая объёмная сцена | Three.js, если задача требует глубины и камеры |

Последние два пункта являются выбором под конкретную задачу, не зависимостями каждого ролика. Не устанавливай подборку библиотек целиком. Для пружины обычно достаточно `spring()` Remotion; для появления линии достаточно `strokeDashoffset` SVG.

## Рабочий пример Remotion

В [assets/remotion/](../assets/remotion/) лежит небольшая изменяемая сцена: рост до границы, тяжёлая плита, остановка, увеличение объёма и движение ниже. Это пример механизма, не обязательный стиль всех роликов.

- `Scene.jsx`: SVG, две композиции по пропорциям, пословные субтитры, подключение готового микса
- `physics.cjs`: состояния плиты по фиксированным шагам 1/60 секунды, интерполяция для произвольного кадра
- `index.jsx`: размер, FPS и длительность из входных параметров
- `remotion.config.js`: существующие пакеты и браузер через окружение процесса
- `package.json`: проверенные версии примера; существующую рабочую установку переиспользовать

Скопируй файлы примера в отдельный проект. В `public/` положи смонтированный звук. `props.json` собери из результата `remap_words.py`, добавив только параметры сцены:

```python
props = {
    **captions,
    'audio': 'mix.wav', 'width': 1080, 'height': 1920, 'fps': 30,
    'style': 'paper', 'title': 'Смысловой заголовок по заданию',
    'actions': {'slab': 1.0, 'volume': 3.6, 'fall': 4.4},
    'subtitleSize': 48,
}
```

`captions` здесь является целым объектом `media-studio.captions.v1`, а `props['captions']` содержит массив слов. `duration` уже находится в результате пересчёта. Имена аудио относятся к `public/`. `style: 'diagram'` меняет пример на чистую схему; `palette` переопределяет `background/ink/red/green`. Цвета и размер текста не меняют речь.

`slab/volume/fall` задаются в секундах **выходного** видео, по соответствующим словам из `captions`. Не переносить числа из примера на чужую речь. Плита освобождается в `slab`, видимое столкновение происходит позже: привяжи момент освобождения так, чтобы удар совпал с репликой и звуком. Действие, которого нет в отрывке, можно поставить после `duration`; `slab` для этого примера должен находиться внутри длительности. Для другого смысла меняй SVG/сцену, не подгоняй речь под плиту.

При внешней установке пакетов задай `MEDIA_REMOTION_PACKAGE` как полный путь к её `package.json`; `MEDIA_EXTRA_MODULES` содержит дополнительные каталоги `node_modules`, разделённые `path.delimiter` текущей ОС. При обычных зависимостях проекта эти два значения не нужны. `MEDIA_BROWSER_EXECUTABLE` обязателен и указывает на уже найденный совместимый браузер. Команда из папки проекта:

```shell
remotion render index.jsx Main out.mp4 --props props.json --codec h264 --audio-codec aac --pixel-format yuv420p
```

## Физика без зависимости от порядка кадров

`Runner`, `requestAnimationFrame`, реальное время и накопление состояния в React-рендерах для экспорта не подходят. Рассчитай весь короткий физический эпизод с нуля фиксированным шагом, сохрани координаты/углы и выбирай состояние по `frame / fps`. Для длинного видео рассчитывай эпизод сцены, а не часовую физическую симуляцию.

Удерживаемое тело Matter.js сначала создавай с конечной массой, затем вызывай `Body.setStatic(body, true)`. При освобождении `Body.setStatic(body, false)` восстановит сохранённые массу и инерцию. В проверенной версии создание сразу с `isStatic: true` оставляло их бесконечными после освобождения и давало `NaN`. Включённая проверка конечности координат останавливает такой рендер с ошибкой.

Проверь состояния до действия, во время удара и после него. Повторный расчёт и запрос кадров в другом порядке должны давать тот же результат. SFX удара размещается по фактическому контакту; декорация не должна менять исходный смысл.

## Приёмка короткого примера

Проверь склейки, несколько смен слов, момент действия и его результат в экспортированном файле. Для движения нужны последовательные кадры вокруг действия, не только кадр раз в секунду. В другом формате меняются композиция и размер текста; голос и выходное время сохраняются, пока не заказан новый монтаж. Для правки стиля сравни неизменяемые `clips/captions/audio/actions` до и после.

Источники API: [кадровое время Remotion](https://www.remotion.dev/docs/use-current-frame), [Matter.Engine](https://brm.io/matter-js/docs/classes/Engine.html), [Matter.Body](https://brm.io/matter-js/docs/classes/Body.html). Пример проверен с Matter.js 0.20.0 и Remotion 4.0.537; совместимость другой версии подтверждается её коротким рендером.
