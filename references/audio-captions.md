# Речь, монтаж звука и субтитры

## Пословные таймкоды

Для производственного распознавания запрошенного исходника используй установленный faster-whisper. Если установлен `transcribe-local-media`, отдельный запрос «сделай расшифровку» остаётся в нём; его контракт на один Markdown сохраняется.

```powershell
& '<asr-python>' -X utf8 '<skill-dir>\scripts\transcribe_words.py' '<source>' --output '<project>\words.json' --language ru
```

`<asr-python>` означает Python среды с faster-whisper и CUDA-библиотеками; `<skill-dir>` означает папку этого навыка. Без `--language` движок определяет язык. Скрипт использует локальный кэш `large-v3`, CUDA/float16, `word_timestamps=True`; сеть для модели и тихий CPU fallback не используются. Он не меняет источник и не перезаписывает несовпадающий результат. Кэш принимается при совпадении SHA-256 источника и конфигурации. Для точечной проверки пропуска `--no-vad` отключает VAD; сначала подготовь нужный интервал, сохранив его смещение в исходнике.

Распознавание не определяет важность момента и не доказывает правильность каждого слова. Сверь термины, числа, имена, отрицания, начало/конец речи и подозрительные вставки на тишине. Таймкод слова является оценкой распознавателя, а не гарантией фонетической точности. Идентификацию участников по именам не выдумывай.

## Единое время

Простой список склеек задаётся в секундах исходника, интервалы полуоткрытые `[start,end)`:

```json
{
  "clips": [
    {"start": 12.0, "end": 20.0},
    {"start": 35.0, "end": 41.0}
  ]
}
```

В этом примере исходное слово на 36-й секунде оказывается на 9-й секунде результата. Вычисление: сумма длительностей предыдущих клипов + время слова - начало текущего клипа. Если в клипе явно задан `rate`, длительность и локальные времена делятся на него. Скорость оригинальной речи меняется только по заданию.

```powershell
python -X utf8 '<skill-dir>\scripts\remap_words.py' '<project>\words.json' '<project>\edit.json' --output '<project>\captions.json'
```

Скрипт работает с одной исходной дорожкой и последовательной склейкой без переходных перекрытий. Он сохраняет исходные времена у каждого выходного слова и выдаёт Remotion Caption-поля в миллисекундах. Отрезание внутри слова отклоняется. Для нескольких источников, crossfade, speed ramp или сложного многодорожечного проекта сделай явное отображение источника в выходное время в коде проекта; не используй этот простой remap как будто он умеет такие операции.

Не накладывай субтитры с исходными таймкодами на сокращённую запись. После изменения EDL пересчитай и голос, и слова, и привязанные сцены. Повторно извлекать аудио или распознавать неизменённый источник не требуется.

## Склейки речи

Режь на естественных границах. Длинная тишина является кандидатом, а не автоматической ошибкой. Сохраняй дыхание и смысловые паузы; не удаляй все промежутки до нуля. Короткие микрофейды могут убрать щелчок, но не исправляют обрезанную согласную. Для точного монтажа декодируй аудио/переэнкодируй выбранные участки: stream copy не гарантирует требуемую точность границы.

Если исходник содержит одновременно голос и музыку, извлечение аудиопотока сохраняет оба. Отдельная чистая речь требует предоставленного stem либо отдельного доступного способа разделения; одного `-vn` для этого недостаточно.

## Субтитры

- Оригинальные слова являются основой; не превращай их незаметно в пересказ.
- Группируй по читаемым фразам, измеряй фактическую ширину. Строки, размер и позиция зависят от формата, стиля и самого текста.
- Слово подсвечивается по выходным таймкодам; нельзя просто равномерно разложить слова по длине предложения.
- Текст не закрывает лицо, смысловую схему или интерфейс. Если одновременно нужен заголовок, он занимает отдельное место либо получает своё время.
- В Remotion удобен массив `{text,startMs,endMs,timestampMs,confidence}` и выбор активного слова по времени кадра. В FFmpeg для оформления используй ASS; SRT хранит текст и время без всего дизайна.
- Проверь реальные границы смены слов/фраз и кадры склеек. Исправление слова не должно незаметно сдвигать соседние слова.

## Обработка и сведение

Сначала определи дефект: общий уровень, перепады, гул, шум, перегруз или маскировка музыкой. Не применяй один «улучшающий» набор фильтров ко всем источникам. Исходный голос остаётся главным.

Для разговорной интернет-версии при отсутствии другого требования разумная отправная цель около -16 LUFS integrated и true peak не выше -1.5 dBTP. Это выбор мастеринга, не обязательное требование всех площадок. Моно, динамичный материал и требования доставки могут потребовать иных целей. Измеряй весь окончательный микс, не только голос.

Для точного нормирования используй два прохода `loudnorm`: первый измеряет, второй использует реальные `input_i/input_tp/input_lra/input_thresh/target_offset`. После сведения измерь экспорт ещё раз. В цифровой тишине значение LUFS может быть `-inf`; это не число для автоматического нормирования.

Музыка/SFX подбираются по роли и реальным ассетам. Под речь понижай музыку или применяй доступный sidechain; необходимые значения определяются миксом, не фиксированным процентом громкости. Шумоподавление и компрессия требуют сравнения до/после. Для движущегося объекта звук привязывай к реальному действию на временной шкале. Музыкальная доля не должна разрезать слово ради идеального beat-grid.

Если установлен `opus-sound-layer`, при запросе детального звукового оформления используй его схему cue sheet. Используй доступную локальную библиотеку звука; не перестраивай её и не скачивай новую модель ради обычного микса. Сохраняй источник/лицензию добавленных ассетов в проекте.

## Проверка звука

Проверь наличие нужного потока, длительность, задержку относительно изображения, измеренные LUFS/true peak, неожиданные паузы и склейки. Прослушивание подтверждай только если реально прослушан экспорт. Пиковый уровень не доказывает разборчивость, шумомер не доказывает естественный тембр. Исправляй конкретный дефект, а не ослабляй критерий после ошибки.
